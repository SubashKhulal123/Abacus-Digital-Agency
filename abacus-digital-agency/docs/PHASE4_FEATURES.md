# Phase 4 — Advanced Production Features

This document covers every feature added in Phase 4, why it was built the
way it was, and where to find it in the codebase. Phases 1–3 covered
architecture, the public site, and the admin CMS; Phase 4 hardens all of
that into something ready for real traffic.

---

## 1. SEO

### Per-page metadata
`frontend/src/components/common/SEO.jsx` is a `react-helmet-async`
wrapper dropped into every page (`Home`, `About`, `Services` + detail,
`Portfolio` + detail, `Blog` + detail, `Careers` + detail, `Contact`,
`404`). It sets:
- `<title>` and `<meta name="description">`
- `<link rel="canonical">`
- Open Graph tags (`og:type`, `og:title`, `og:description`, `og:image`, `og:url`)
- Twitter Card tags (`summary_large_image`)
- Optional `noindex` for pages that shouldn't rank (404)

### Structured Data (JSON-LD)
The same `SEO.jsx` file exports builder functions so each page only
supplies data, not markup:
- `buildOrganizationSchema` — Home page
- `buildBreadcrumbSchema` — Project detail pages
- `buildArticleSchema` — Blog post pages
- `buildJobPostingSchema` — Job detail pages (includes salary when the
  admin has marked it public)

### Sitemap & robots.txt
Both are **dynamically generated by the backend**, not static files, so
they always reflect real published content:
- `GET /sitemap.xml` (`backend/src/controllers/sitemap.controller.js`) —
  static routes + every published project/blog, active service/job,
  each with a real `<lastmod>` from `updatedAt`
- `GET /robots.txt` — disallows `/admin` and `/api`, points to the sitemap

Both are mounted at the domain root in `app.js` (not under `/api/v1`),
which is where crawlers expect them.

## 2. Performance

### Image optimization
`frontend/src/utils/imageOptimization.js` injects Cloudinary
transformation parameters (`f_auto,q_auto,w_<size>`) into any Cloudinary
URL, so images are served as WebP/AVIF at the right size instead of a
full-resolution original. `LazyImage.jsx` wraps this with:
- native `loading="lazy"` (or `eager` via a `priority` prop for
  above-the-fold images)
- a skeleton placeholder shown until the image actually loads (no layout
  shift, no broken-image flash)
- optional `srcSet` generation across 4 breakpoints via `buildSrcSet`

### Code splitting & bundling
Already established in Phase 1–3 and extended here: every route is
`React.lazy`-loaded, and `vite.config.js` manually chunks vendor code
(`react-vendor`, `animation-vendor`, `query-vendor`, `form-vendor`,
`admin-vendor` for Recharts/Quill) so a visitor to the public site never
downloads admin-only code. Verified via production build after every
phase — see the root `README.md` for exact module/chunk counts.

### Caching
- **Client-side**: React Query (`staleTime`, `keepPreviousData` on
  paginated lists) — established in earlier phases, unchanged here.
- **HTTP caching**: `backend/src/middlewares/cacheControl.middleware.js`
  applies resource-appropriate `Cache-Control` headers to public GET
  endpoints — short TTLs for frequently-changing content (projects,
  blogs: 60s), longer for near-static content (technologies, FAQs: 600s),
  using `stale-while-revalidate` so a CDN/browser can serve instantly
  while refetching in the background. Write endpoints (contact,
  newsletter, applications) are never cached.
- **Offline/PWA cache**: see section 6.

### Infinite scroll vs. pagination
Both patterns are implemented deliberately, not redundantly:
- **Portfolio** uses classic numbered pagination (`?page=`) — appropriate
  for a bounded, browsable case-study archive.
- **Blog** uses infinite scroll (`useInfiniteBlogs` in `useContent.js`,
  built on React Query's `useInfiniteQuery`) with a
  `useIntersectionObserver`-based sentinel — appropriate for a
  chronological feed people scroll through.

## 3. Search

### Global search (Cmd+K)
`frontend/src/components/common/GlobalSearch.jsx` is a command-palette
overlay, opened via a search icon **or Cmd/Ctrl+K** from both the public
navbar and the admin topbar. It debounces input (`useDebounce`, 300ms),
queries `GET /api/v1/search?q=`, and renders grouped, keyboard-navigable
results (arrow keys + Enter) across projects, blog posts, services, and
team members.

The backend endpoint (`backend/src/controllers/search.controller.js`) is
a deliberately simple regex search across 1–2 fields per resource, capped
at 5 results each — sufficient for a site this size without the
operational overhead of a dedicated search engine (Algolia/Elasticsearch)
that would be overkill here.

### Filtering
Category filters on Portfolio and Blog (built in Phase 2) remain the
primary filtering UI; the admin `DataTable` adds search + sortable
columns for every admin list view.

## 4. Newsletter, Email, and Contact

### Email templates
`backend/src/utils/emailTemplates.js` centralizes every transactional
email the app sends (contact admin notification, contact auto-reply,
contact reply, newsletter welcome, application admin notification,
application confirmation, application status update) as named functions
returning `{ subject, html }`. Controllers were refactored in this phase
to call these instead of inlining HTML strings — one place to update
branding/copy, not six.

### Contact form, career applications, newsletter
Functionally unchanged from Phase 2 (already SMTP-backed, validated,
rate-limited) — Phase 4 adds toast feedback on the frontend
(`react-hot-toast`) alongside the existing inline success/error states,
so submission feedback is impossible to miss even if the user has
scrolled away from the form.

## 5. Error & Edge-Case Pages

| Page | Trigger | File |
|---|---|---|
| 404 | Unmatched route | `pages/NotFound.jsx` (now `noindex` via SEO) |
| 500 | Uncaught render error anywhere in the tree | `components/common/ErrorBoundary.jsx` → `pages/ServerError.jsx` |
| Maintenance | `SiteSettings.maintenanceMode.isEnabled` | `pages/Maintenance.jsx`, gated in `layouts/MainLayout.jsx` |

**Maintenance mode** is enforced on both ends:
- Backend: `middlewares/maintenanceMode.middleware.js` is mounted after
  `/auth` and `/admin` (and `/settings`) but before every other public
  route, so it blocks the public API with a 503 while never locking
  admins out of turning it back off. `/settings` is deliberately exempt
  since it's the endpoint that tells the frontend maintenance mode is
  active in the first place.
- Frontend: `MainLayout` checks `useSiteSettings()` on every render and
  swaps in the `Maintenance` page instead of the routed content when
  enabled — `/admin/*` uses a separate layout entirely, so it's
  unaffected.

**500 handling**: `ErrorBoundary` wraps the entire app in `App.jsx`. It's
a class component (required — error boundaries can't be hooks) that
catches any render-phase error in its subtree and renders `ServerError`
with a "Try Again" button that resets the boundary.

## 6. Loading States & Notifications

- **Skeletons**: `components/common/Skeleton.jsx`, used throughout every
  section/page/admin table while data loads (established Phase 2–3,
  unchanged here).
- **Toast notifications**: `react-hot-toast`, themed to follow the active
  color theme + dark/light mode (`ThemedToaster` in `App.jsx` reads CSS
  variables directly, so toasts always match whichever of the 5 themes is
  active). Wired into: contact form, newsletter (footer + dedicated
  section), admin login, admin resource create/update, admin delete/bulk
  delete, admin settings save, admin message reply, job application
  submission.
- **Route transitions**: `PageTransition.jsx` (Phase 2) + a spinner
  fallback (`PageLoader`) shown during lazy-chunk loading — unchanged,
  confirmed still working after all Phase 4 route additions.

## 7. Security

Building on Phase 1's Helmet/rate-limiting/Zod-validation/sanitization
foundation:

- **Explicit CSP**: `app.js`'s Helmet config now sets a real
  Content-Security-Policy (`default-src 'self'`, image sources
  whitelisted to Cloudinary/Picsum, no `object-src`, no framing) rather
  than relying only on Helmet's defaults — documented in `app.js` inline.
- **Rate limiting**: unchanged tiering from Phase 1 (global / strict
  auth / public-write limiters) — still in force on every mutating
  endpoint.
- **Input validation**: every write endpoint remains Zod-validated
  (backend) and React-Hook-Form + Zod validated (frontend) — no new gaps
  introduced by Phase 4's additions (search is read-only + regex-escaped
  by construction since it's built from `RegExp(q, 'i')` on a
  user-controlled but non-executable string used only in Mongoose
  queries, not `eval`'d or reflected as HTML).
- **XSS**: the existing plain-text sanitizer (Phase 1) still guards
  contact/newsletter/application bodies; rich-text blog content remains
  intentionally un-stripped (admin-authored, not user-submitted) as
  documented in Phase 1's ARCHITECTURE.md.

## 8. Accessibility

- **Skip link**: `MainLayout.jsx` now includes a "Skip to main content"
  link, visually hidden until focused (`sr-only focus:not-sr-only`) —
  standard pattern for keyboard/screen-reader users to bypass the navbar.
- **Focus states**: global `:focus-visible` ring (Phase 1) confirmed
  intact across all new interactive elements.
- **ARIA labels**: added to every icon-only control introduced in this
  phase (search triggers, table row/edit/delete actions, select-all
  checkbox) so screen readers announce their purpose instead of silence.
- **Reduced motion**: `CustomCursor`, Lenis smooth scroll, and all
  Framer Motion entrance animations already respect
  `prefers-reduced-motion` (Phase 2) — unaffected by this phase's
  additions.

## 9. PWA / Offline Support

`vite-plugin-pwa` (Workbox under the hood) generates a service worker at
build time:
- **Manifest** (`vite.config.js` → `manifest` option): name, theme/
  background color, standalone display mode, and real PNG icons at
  192×192, 512×512, and a maskable 512×512 variant (generated to match
  the brand's midnight-violet palette — see
  `frontend/public/icons/`).
- **Runtime caching**:
  - API calls (`/api/v1/*`) — `NetworkFirst` with a 5s timeout, falling
    back to a 1-day cache, so the app stays browsable (from cache) if the
    network drops mid-session.
  - Cloudinary/Picsum images — `CacheFirst`, 30-day cache, since images
    rarely change once uploaded.
- **Auto-update**: `registerType: 'autoUpdate'` — new deployments are
  picked up without the user needing to manually clear anything.

This is genuinely functional offline support for a previously-visited
session, not just a manifest file for an "installability" checkbox.

## 10. Reusable Hooks Added This Phase

| Hook | Purpose | Where it's actually used |
|---|---|---|
| `useDebounce` | Delays a value update until input settles | `GlobalSearch` |
| `useIntersectionObserver` | Ref-based viewport-visibility tracking | `Blog.jsx` infinite scroll sentinel |
| `useLocalStorage` | Safe, JSON-parsed localStorage-backed state | Available for future features (theme/mode persistence already had its own simpler implementation predating this hook) |
| `useMediaQuery` | Reactive CSS media query | Available for responsive logic beyond Tailwind breakpoints |
| `useClickOutside` | Outside-click detection | `ThemeSwitcher`, `NotificationsDropdown`, admin `Topbar` profile menu — **replacing** three copies of the same inline `useEffect` that existed before this phase |

Every hook above other than `useLocalStorage`/`useMediaQuery` is verified
in active use, not speculative scaffolding — see the "where it's actually
used" column.
